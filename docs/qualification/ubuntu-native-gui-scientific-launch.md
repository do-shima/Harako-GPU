# Ubuntu native GUI scientific launch qualification

Classification: `UBUNTU_NATIVE_GUI_ONE_PASS_TWO_PASS_APPTEST_QUALIFIED_BROWSER_RUNTIME_BLOCKED`.

The local Streamlit GUI completed two new immutable C1 ERR188044 one-million-pair runs on the receipt-backed `ubuntu_native_rtx3090_ram128_v1` host. G1 used Harako-native one-pass and G2 used Harako-native two-pass. In both cases the GUI itself scanned and validated the FASTQ pair, evaluated native launch eligibility, created and reviewed the plan, prepared the run, and launched the product controller. Neither run was created, prepared, or started through the CLI or a direct Nextflow command.

G1 froze `harako_native_v1`, `parabricks_star_one_pass_workstation`, `ubuntu_native_rtx3090_ram128_one_pass_42gb_v1` (42.GB and 12 CPUs), `--two-pass-mode None`, FeatureCounts `-t exon -g gene_type`, and recommended-only Salmon 2.5.1 with explicit ISR. G2 froze the same scientific inputs and controller quantification route while selecting `parabricks_star_two_pass_high_memory`, `ubuntu_native_rtx3090_ram128_two_pass_96gb_v1` (96.GB and 12 CPUs), and `--two-pass-mode Basic`. Both used the six-role selected Harako-native image closure, required no nf-schema plugin, and executed no CPU STAR or hidden Salmon task.

Both runs reached `COMPLETED`. Each Nextflow trace contained exactly FASTP, PARABRICKS_RNA_FQ2BAM, PUBLISH_ALIGNMENT_CONTRACT, FEATURECOUNTS_BIOTYPE_QC, and MULTIQC, with five completed and zero failed processes. The controller completed all nine tasks. Canonical backend-output manifests, BAM/BAI validation, junctions, STAR GeneCounts, FeatureCounts gene-type QC, Salmon 2.5.1, transcript/gene matrices, MultiQC, and Nextflow report/timeline/trace/DAG were present. GUI deep verification and an independent public read-only deep verification both passed with 35 validated artifacts per run.

The GUI created sanitized support bundles for both runs. Independent ZIP audits found no FASTQ, BAM/BAI, quantification output, matrix, reference/index data, credentials, or unredacted private absolute paths. The completed G1 run was rediscovered after AppTest rerun, completed runs did not offer Resume, and the retained fail-once fixture exposed Resume without offering mutable backend/profile/input controls. Stale-lock presentation and malformed-PID-to-stale handling passed their focused probes.

An explicit nf-core reference plan was also created through the GUI without preparing or starting it; `nfcore_rnaseq_3_26_reference` remained frozen in its plan. Native eligibility remained fail-closed when the installed receipt was missing. Active execution remained restricted to local ext4 storage, and WD Gold remained rejected for active work.

Four reproducible GUI-integration defects were repaired with focused regression tests before the successful runs: environment defaults overwrote an explicit backend selection, the immutable product-CLI qualification evidence was not consulted for the unchanged installed receipt, the GUI rejected the backend-aware capability snapshot, and GUI start validated a frozen plan as though source-plan sibling files still existed. The fixes preserve the receipt, scientific contracts, frozen inventory, and controller boundary. Final regression completed with 454 passed tests and the single explicit browser opt-in skip.

No supported Chrome, Chromium, or Edge executable was installed on this Ubuntu host. Streamlit AppTest and HTTP loopback health/root checks passed, but actual-browser runtime qualification is therefore `ACTUAL_BROWSER_RUNTIME_UNAVAILABLE`. This result qualifies the native Ubuntu GUI orchestration path for the fixed C1 envelope only. It does not rerun full ERR188044, re-evaluate Salmon 1.10.3, qualify CPU STAR, enable Harako-native execution on Windows/WSL, implement automatic archive/deletion, establish biological truth, or provide clinical/diagnostic validation.
