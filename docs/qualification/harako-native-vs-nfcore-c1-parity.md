# Harako-native versus nf-core C1 backend parity qualification

Classification: `HARAKO_NATIVE_C1_ONE_PASS_TWO_PASS_STRICT_SCIENTIFIC_PARITY`.

The public product CLI lifecycle completed for four immutable C1 runs on the verified `ubuntu_native_rtx3090_ram128_v1` host. The prescribed order was Harako-native one-pass (N1), nf-core reference one-pass (R1), nf-core reference two-pass (R2), then Harako-native two-pass (N2). N2 was repeated once after a monitoring-only defect was fixed; the superseded successful N2 remains retained. No full ERR188044 run or Salmon version-comparison run was repeated.

Both backend pairs achieved strict scientific parity. Processed FASTQ gzip bytes and decompressed streams were identical. The normalized Parabricks scientific arguments, images, profiles, resource contracts, read groups, and fixed STAR options were identical. For both modes, the uncompressed `samtools view` record streams had identical SHA-256 values across backends: `aa78911e6e7bd89da35dd45171a83c1a65c0b9569174a7c7917e16be240e1874` for one-pass and `2097b8cff067213d5e3bbadee3eeea55660386efa7b853d4ba119ef5d6e6cd40` for two-pass. BAM container bytes differ because the reference backend performs a separate Samtools sort and records extra `@PG` provenance; scientific `@HD`, `@SQ`, and `@RG`, record order/content, flagstat, idxstats, and Samtools checksums are equal.

Junction rows and every numeric field are exact. All STAR GeneCounts columns and the selected ISR counts are exact. FeatureCounts used `-t exon -g gene_type`; the 38-row biotype universe, counts, and assignment summaries are exact. The reference backend uses its contig-filtered equivalent GTF path and a different output filename, which is a representation difference only. Salmon 2.5.1 `quant.sf`, `quant.genes.sf`, all six transcript/gene matrices, dimensions, and sample order are byte-identical across each pair. MultiQC overlapping fastp and STAR metrics are exact, FeatureCounts evidence is traceable in both reports, and nf-core-only QC is classified `REFERENCE_BACKEND_ADDITIONAL_QC`.

The Harako-native DAG contained exactly FASTP, PARABRICKS_RNA_FQ2BAM, PUBLISH_ALIGNMENT_CONTRACT, FEATURECOUNTS_BIOTYPE_QC, and MULTIQC. It used the minimal selected image closure and no nf-schema plugin, nf-core pipeline snapshot, hidden Salmon, runtime module fetch, image pull, or CPU STAR fallback. The reference backend retained nf-core/rnaseq 3.26.0, its fixed patches, nf-schema 2.5.1, and the qualified 18-image closure. Salmon remained controller-owned for both backends.

All successful runs passed deep artifact verification and produced sanitized support bundles with no FASTQ, BAM/BAI, quantification output, matrix, reference/index, container layer, plugin binary, or credential. Performance and storage observations are descriptive only. R1 includes an external controller interruption and public resume, so its gross wall time is not a benchmark; observed active intervals and task traces are recorded separately.

Implementation repairs were limited to product defects: native profile launch, self-copy-safe publication, stranded paired FeatureCounts, pinned MultiQC data-directory naming, exact named-session resume, attempt-local Nextflow observers, and partial work-size monitoring. Every repair had a focused failing test before the fix and a separate commit. None changed FASTQ, reference, STAR index, Parabricks scientific flags, resource contracts, Salmon inputs/options, or parity gates.

This evidence qualifies C1 parity only on the exact Ubuntu host receipt and fixed assets. It does not establish full-size capacity, arbitrary-sample generality, biological truth, clinical use, CPU STAR qualification, Windows/WSL Harako-native execution, cross-host equality, full nf-core feature parity, or scientific superiority. Native GUI scientific launch remains guarded.
