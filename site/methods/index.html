Methods

A compact Nextflow workflow with version-pinned analysis settings

Harako-native runs the tested Parabricks alignment and QC steps. The shared Harako controller performs versioned quantification, validation, matrix generation, and evidence recording.

Harako-native workflow

  1. fastp preprocessing
    Uses a pinned container image and produces the processed FASTQ pair used downstream.
  2. Parabricks alignment
    PARABRICKS_RNA_FQ2BAM uses the fixed one-pass or two-pass arguments and profile-specific resources.
  3. Alignment output publication
    PUBLISH_ALIGNMENT_CONTRACT records outputs in a backend-independent manifest.
  4. FeatureCounts biotype QC
    FEATURECOUNTS_BIOTYPE_QC uses -t exon -g gene_type for GENCODE 49.
  5. MultiQC reporting
    Collects the defined QC results and links to their source metrics.

Salmon is not run inside Nextflow. The Harako controller quantifies the same processed paired FASTQ with an explicit library type and six threads, so quantification is performed only once for each selected profile.

Alignment profiles

One-pass workstation

--two-pass-mode None --low-memory --quantMode TranscriptomeSAM GeneCounts --sjdb-overhang 74

Only the Parabricks process receives 42 GB and 12 CPU cores.

Two-pass high-memory

--two-pass-mode Basic --low-memory --quantMode TranscriptomeSAM GeneCounts --sjdb-overhang 74

Only the Parabricks process receives 96 GB and 12 CPU cores.

Users cannot provide free-form scientific arguments or resource overrides. Harako-GPU does not increase memory dynamically and does not fall back to CPU STAR.

Counts and quantification

For the fixed GRCh38.p14 / GENCODE 49 reference pack, FeatureCounts uses feature type exon and group type gene_type. This output supports biotype QC and remains separate from STAR ReadsPerGene.out.tab GeneCounts.

Salmon 2.5.1 is the default for new analysis series. Salmon 1.10.3 remains available for compatibility. Its repeated runs were highly concordant, but not numerically identical. The compare-both mode runs the two profiles sequentially against the same processed FASTQ.

Results generated with different Salmon versions can differ because of software implementation, index construction, and execution behavior—not only because of floating-point rounding.

Harako-GPU records and pins the Salmon version, container image, index, options, and library type for every run. Results from different Salmon versions should not be combined without explicitly accounting for the version difference.

Run lifecycle and reference backend

Before execution, the analysis plan records the workflow backend, alignment and quantification profiles, containers, reference data, outputs, resources, execution context, and approval hash. Preparation checks those requirements again. Start and resume use structured arguments with shell=False, persistent PID, lock, and state files, and numbered attempts. A completed run cannot be resumed. The GUI uses the same services for deep output verification and support-bundle creation.

The nfcore_rnaseq_3_26_reference backend retains its pinned pipeline commit, qualified patches, offline nf-schema@2.5.1 requirement, and 18-image set for comparison and expert use. Harako-native does not require nf-schema or that full image set.

Limitations

  • This is a public research alpha for research use only. It is not intended for diagnostic or clinical use.
  • Qualification covers the stated host and reference only. Other RTX systems, custom references, and arbitrary human FASTQ inputs are not yet qualified.
  • CPU STAR and DESeq2 are unavailable. No matched CPU speed benchmark is provided, and not every workflow stage uses the GPU.
  • Automatic archiving and deletion are not implemented. Users may explicitly archive a successful run only after its results have been verified.
  • An actual Ubuntu browser was unavailable during GUI qualification; AppTest, HTTP checks, and scientific C1 GUI runs passed.
  • Cross-host equality and biological truth were not evaluated.
The evidence supports the documented workflow settings and retained public inputs. It does not validate biological interpretation, experimental design, clinical performance, or deployment on other systems.
