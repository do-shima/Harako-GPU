Public alpha installation

Exact assets and receipts are part of the runtime contract

Installation is operator-managed. Harako-GPU never accepts vendor terms, logs in to a registry, or downloads the scientific asset closure during plan preparation.

Fresh-clone source installation

git clone https://github.com/do-shima/Harako-GPU.git
cd Harako-GPU
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
harako-gpu --version
harako-gpu doctor --json
harako-gpu ui --no-browser

The alpha is installed from source. A release-download button is intentionally absent until a release exists.

Provision scientific assets separately

  1. Install Docker Engine and NVIDIA Container Toolkit using their official documentation.
  2. Obtain Parabricks 4.6.0-1 from official NVIDIA NGC. Review and accept NVIDIA terms yourself; Harako-GPU provides no terms-acceptance command.
  3. Provision the exact fixed public-task images. Preparation verifies identities and fails before launch if the selected closure is incomplete; it does not pull.
  4. Provision the fixed reference pack and version-specific indices outside Git.
  5. Copy an operator-issued host qualification receipt to <runtime-root>/host-profiles/ubuntu_native_rtx3090_ram128_v1.json. Plan creation does not generate or mutate it.
  6. Run harako-gpu doctor --json, inspect capabilities, then create and review a non-executing plan.

No Parabricks image, reference, index, plugin binary, container archive, FASTQ, or BAM is distributed with this repository. Each asset retains separate terms.

Candidate and unsupported setups

Candidate only

Other native Ubuntu releases, RTX GPUs, RAM capacities, driver versions, storage layouts, or custom references remain candidates requiring separate prospective qualification. Hardware detection alone never makes them available.

Unsupported for the qualified route

Windows/WSL full-human BAM on the fixed 64 GB host, CPU STAR, macOS, active work on NTFS/fuseblk/SMB/CIFS/NFS/WD Gold, /mnt/c, /mnt/d, or unsafe paths.

Qualification is bound to exact report hashes, runtime provenance, image identities, reference/index identities, execution context, and local filesystem checks—not a marketing hardware label.
