Validated containers, reference assets, and host qualification records are required

The user or system administrator provisions these requirements before analysis. Harako-GPU does not accept vendor terms, sign in to registries, or download scientific containers and data while preparing a run.

Tested setup

Operating systemUbuntu 24.04.4 LTS running directly on Linux, not through WSL
GPUNVIDIA GeForce RTX 3090 with 24 GiB VRAM and a compatible driver
Memory128 GB of physical RAM
Active storageA local ext4 SSD with sufficient free capacity; WD Gold and network storage must not be used as the Nextflow workDir
Container runtimeDocker Engine and NVIDIA Container Toolkit
Workflow engineJava 17 or later and Nextflow 25.04.3
ApplicationPython 3.11 or later and Harako-GPU v0.1.0-alpha.1
Alignment imageParabricks 4.6.0-1 with validated offline provenance and a matching runtime image ID
Reference dataThe fixed GRCh38.p14 / GENCODE 49 reference pack, STAR 2.7.2a index, and the selected Salmon 2.5.1 and/or 1.10.3 index
Qualification recordsA valid host qualification receipt, matching reports, and the required plugin and container-image records for the selected backend

Install from a fresh source clone

You can also install the application directly from source:

git clone https://github.com/do-shima/Harako-GPU.git
cd Harako-GPU
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
harako-gpu --version
harako-gpu doctor --json
harako-gpu ui --no-browser

Provision the required containers and reference data

  1. Install Docker Engine and NVIDIA Container Toolkit by following their official documentation.
  2. Obtain Parabricks 4.6.0-1 from official NVIDIA NGC. You must review and accept NVIDIA's terms independently; Harako-GPU does not provide a command that accepts those terms.
  3. Provision the required public task-container images with their pinned identities. Run preparation verifies them and stops before launch if any selected image is missing; it never pulls images automatically.
  4. Place the fixed reference pack and version-specific indices outside the Git repository.
  5. Copy a host qualification receipt issued by the system administrator to <runtime-root>/host-profiles/ubuntu_native_rtx3090_ram128_v1.json. Creating a plan does not generate or modify this file.
  6. Run harako-gpu doctor --json, review the reported capabilities, and then create and review a plan without starting a scientific run.

This repository does not distribute Parabricks, reference data, indices, plugin binaries, container archives, FASTQ, or BAM files. Their licenses and terms apply independently.

Other and unsupported setups

Not yet qualified

Other Ubuntu releases, RTX models, RAM capacities, driver versions, storage layouts, and custom references require separate prospective qualification. Hardware detection by itself is not enough to enable a scientific run.

Not supported by the validated route

The validated route does not support full-human BAM generation on the fixed 64 GB Windows/WSL host, CPU STAR, macOS, or active work on NTFS, fuseblk, SMB, CIFS, NFS, WD Gold, /mnt/c, /mnt/d, or unsafe paths.

Qualification depends on validated report hashes, container provenance, image and reference/index checksums, the execution context, and local-filesystem checks. A hardware model name alone is not sufficient.
